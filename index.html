Golem-One XL · training in progress

A decision model,
built from scratch in Go.

Golem is a GPT-style transformer where every layer was written by hand in Go, following the paper that introduced it. Golem-One XL reads that same network in a new way. You ask it typed questions and it returns a probability for every allowed answer. It answers every question in one pass and cannot give an answer that wasn't offered.

The idea

One transformer, two ways to read it.

A token-by-token model answers by writing text: one full pass per token, 50,257 possible tokens each time, and nothing stops it writing an answer that isn't on the list. Golem-One reads the same weights differently. It reads the state once, answers every question in a single further pass, and scores only the answers you declared.

Why LayerNorm comes before each sub-layer. The original diagram put LayerNorm after attention and after the feed-forward network. That is the post-LN layout of the 2017 transformer and GPT-1. Golem moved it before each sub-layer (pre-LN, as in GPT-2) for two reasons: deep stacks train more stably, and it is the only way OpenAI's released GPT-2 weights load unchanged. Golem-One depends on those weights.

How Golem-One works

From next-token prediction to System One.

The idea comes from TypeSafe AI's Jev, which they call a "System One" model after the fast, intuitive system 1 of dual-process psychology. We adopted its interface and its guarantees, but not its model. Instead of a new network, Golem-One gets them from three changes in how the existing transformer is read.

① A label per option

Every option is exactly one token

Options are listed under the labels A–Z, and 1–255 beyond that. Each label is a single GPT-2 token, and the prompt ends at Answer:. Training and inference use the exact same tokens.

<|endoftext|>State: Hi, I was charged twice for my order #4471 yesterday… Question: What is this ticket about? Options: A) billing: payments, charges, refunds B) bug: something in the app is broken Answer:

② The segment mask

Read the state once, answer every question in parallel

The state fills the attention cache once. Then every question runs in one pass as its own segment: it sees the whole state and its own tokens, and never another question. Each result matches a separate forward pass to 10⁻⁴. Hover or tap a row.

③ The restricted readout

Score only the K declared answers, never the 50,257 others

At each question's Answer: position a generator would score every token in the vocabulary. Golem-One multiplies the final hidden state h only by the tied embedding rows e of its option labels, and renormalizes:

p(k) = exp(eℓₖᵀ h / T)Σj=1..K exp(eℓⱼᵀ h / T)     c = 1 − H(p) / log K

For a 4-option question on the medium model, the readout costs 4 × 1,024 multiply-adds instead of 51 million. T is a temperature fitted on held-out data. It changes how sure the model says it is, never which answer it picks.

Validity by construction

Probability exists only for declared options. No text is generated, so there is nothing to parse, and whatever the weights are, the model cannot produce an answer that wasn't offered. Training makes the answers correct; the construction already makes them valid.

Golem-One XL · training

A 1.56B model on two free GPUs.

At this scale, a fine-tuned model's quality depends mostly on two things: the size of the pre-trained model and the amount of good data. So we chose GPT-2's largest shape. Fully fine-tuning it needs about 25 GB for weights and optimizer state, but a free Kaggle T4 has 15 GB. Four additions to Golem's own CUDA engine close that gap.

fp16

Mixed precision

Matrix products run on tensor cores in fp16. Master weights, gradients and optimizer state stay fp32, and dynamic loss scaling prevents underflow.

2.6–2.9× faster
r16

LoRA

Every linear weight is frozen, kept in fp16 only, and adapted by a rank-16 product. Checkpoints merge back into ordinary Golem weights.

1.33% trained
K

Options-only loss

On decision rows the softmax runs over the answer labels only, exactly as the model is read. Training optimizes what is served.

train = serve
×2

Two GPUs

Micro-batches are split across both T4s and the gradients summed before each identical update. Tested to match a one-GPU run.

2,180 tok/s

GPU memory for XL

Computed from the engine's allocator, for sequences of up to 384 tokens.

What it learns from

549,223 human-labeled questions from 28 open datasets, plus 39,740 human explanations and 60,000 Snake positions. Option order is shuffled so the model has to read the options.

A game is just another decision

Golem-One plays Snake.

The board on the left is exactly the state text Golem-One reads: one character per cell. The question is "Which way should the head move next, to eat the apple without ever crashing?" and the options are up, down, left and right. Snake isn't a separate model. It is one of Golem-One's skills, trained in the same XL run.

apples: 0moves: 0highlighted: the expert's label, the training target

This demo runs a re-creation of the expert player in your browser. Its rule is to take the shortest path to the apple only if the tail is still reachable afterwards, and otherwise to follow the tail. After training, Golem-One keeps learning from its own games, updating its own weights with REINFORCE through the Golem API.
